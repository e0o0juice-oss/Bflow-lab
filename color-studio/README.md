# 색의 발견 · Color Studio

180분 강의안과 참여자 워크북을 연결하는 독립 웹앱. Node.js 22 이상, 외부 런타임 패키지 없이 실행한다. 기존 BFLOW 앱과 서버는 변경하지 않았다.

## 실행

```bash
cd /workspace/Bflow-lab/color-studio
npm start
```

기본 포트는 8040. 접속 경로는 `/color-studio/`, 상태 확인은 `/color-studio/api/health`다. 루트 경로도 앱으로 이동한다. Python 정적 서버나 GitHub Pages만으로는 수업 동기화·저장·공유를 제공하지 못한다.

환경 변수:

- `PORT`: 서버 포트. 호스팅 플랫폼이 제공하는 포트를 사용한다.
- `PUBLIC_ORIGIN`: 외부 운영 시 실제 HTTPS origin을 지정한다. Render에서는 플랫폼이 제공하는 `RENDER_EXTERNAL_URL`을 자동 사용하므로 생략할 수 있다. 예: `https://color.example.com`. 경로나 마지막 `/` 없이 입력한다. 리버스 프록시 뒤에서 출처 검사와 Secure 쿠키를 맞추기 위해 필요하다. 비밀 값이 아니다.
- `COLOR_DATA_DIR`: 기록과 업로드 이미지의 저장 디렉터리. 기본은 이 폴더의 `.data/`이며 Git에서 제외한다. 외부 운영 시 영구 디스크 경로를 지정한다. 임시 디스크의 배포·컨테이너 재생성은 파일을 잃을 수 있다.

단일 Node 인스턴스로 운영한다. 파일 저장을 공유하지 않는 여러 인스턴스로 분산하지 않는다. 외부 운영에서는 HTTPS와 영구 디스크가 필요하다. 수업 중 파일을 직접 편집하거나 배포하지 않는다. 데이터 디렉터리에는 인증 해시·별명·개인 기록·이미지가 있으므로 정적 파일로 제공하지 않는다. 백업도 동일하게 보호하고 보관 만료에 맞춰 삭제한다.

## 강사 사용 순서

1. 실제 학생들이 접속할 수 있는 주소로 열고 **강사 · 새 수업 만들기**를 누른다. 방을 만든 브라우저에 제어권을 발급하며 비밀 복구 코드로 다른 브라우저에서 이어 진행할 수 있다. 수업 코드를 아는 사람도 기존 강사 권한을 얻지 못한다.
2. **수업 설정**에서 5~6개 조, 9단계의 시간·이름, 계절/느낌 이름, 비교 색상 묶음·색 이름/번호·화면 색을 확인한다. 묶음마다 2~12색, 묶음/계절 각각 1~12개를 지원한다. 실제 키트 확인 전에는 예시로 표시된다. 기본 실물 비교 순서는 빨강→핑크→초록→파랑이다.
3. 생성된 QR·참여 링크·6자리 코드를 공유한다. 학생은 별명과 조를 선택한다. 학생은 조를 직접 변경할 수 없다. 잘못된 조로 참여했다면 자료 공유 전에 강사가 진행 체크에서 조를 수정한다.
4. **발표 화면 새 창으로**를 눌러 같은 강사 브라우저의 별도 창을 프로젝터로 옮긴다. 발표 화면에는 강사 노트·학생 기록·조원 댓글·별명을 전달하지 않는다. 별도 기기의 발표 연결 기능은 제공하지 않는다.
5. 강사 화면에서 단계, 단계 안의 슬라이드, 활동 시작/종료, 타이머, 단계 연결을 제어한다. 단계 이동은 타이머를 해당 단계 기본 시간으로 초기화하고 정지한다. 슬라이드 이동은 시간을 초기화하지 않는다. **활동·타이머 시작**으로 함께 시작하고 정지할 수 있다. 타이머 단독 조절도 지원한다.
6. 단계 연결이 켜져 있으면 학생을 현재 단계로 안내한다. 학생이 입력 중이면 화면을 강제로 바꾸지 않고 ‘저장하고 현재 단계로’ 안내를 띄운다. 이전 기록은 연결 상태와 관계없이 열 수 있다. 연결을 끄면 학생이 자유롭게 활동을 탐색한다.
7. 조별 60분 실습은 6명 기준 각 8분과 마지막 재비교 12분으로 운영한다. 모델·천 교체·관찰·기록 안내 역할을 순환한다. 강사 한 명이 모두를 개별 진단한다고 약속하지 않고 재비교 요청이 있는 조를 우선 방문한다.
8. **스타일 공유 열기** 후 이미지·선택 이유·같은 조 피드백을 받는다. 작성자가 별도 체크한 게시물만 발표에 올릴 수 있다. 동의 철회·삭제 시 현재 발표에서도 제거한다. 얼굴 사진은 필요 없다. 이미지는 강사와 같은 조에게 보인다.
9. 마무리 전에 학생에게 관찰과 피드백 다운로드 또는 인쇄/PDF 저장을 안내한다. 수업 종료는 새 기록·업로드·댓글을 막지만 조회·다운로드·발표 동의 철회·본인 게시물 삭제는 가능하다. 영구 삭제는 별도 수업 코드 입력으로 확인한다.

## 저장·권한·연결 복구

- 강사와 학생 인증은 HttpOnly·SameSite 쿠키, 서버에는 토큰의 SHA-256 해시만 보관한다. HTTPS 운영 시 `PUBLIC_ORIGIN`을 설정하거나 Render의 `RENDER_EXTERNAL_URL` 자동 제공을 확인한다. 학생의 별도 기기 복구 기능은 없다. 강사는 미리 발급해 저장한 비밀 복구 코드로 제어권을 복구할 수 있다.
- 학생 개인 워크북 API는 본인만 제공받는다. 강사에게는 별명·조·관찰한 색상 수·재비교 요청·접속 상태만 전달한다. 공개 게시판은 서버에서 조를 검사하고 강사는 진행을 위해 모든 조 게시판을 볼 수 있다.
- 입력은 기기에 즉시 기록 후 서버에 순차 저장한다. 동일 저장 요청 재시도는 중복 반영하지 않으며, 버전이 다른 탭의 덮어쓰기를 거부한다. 충돌 시 기기 기록을 먼저 내려받고 ‘서버 기록 불러오기’를 선택한다. 브라우저 저장 공간이 막혔으면 알림과 저장 상태를 확인한다.
- HTTPS 또는 localhost에서 서비스 워커 설치가 끝난 뒤에는 정적 앱 화면을 오프라인에서도 열 수 있다. API·이미지·강사 노트는 서비스 워커에 캐시하지 않는다. 같은 브라우저의 기존 개인 기록을 임시 복원하고 연결 후 권한과 저장을 다시 확인한다. 처음 방문부터 오프라인이거나 브라우저 저장소를 삭제하면 복원할 수 없다. 일반 HTTP의 원격 IP 주소에서는 서비스 워커가 지원되지 않을 수 있다.
- 오프라인 입력은 유지된다. 복귀 후 ‘기기와 서버에 저장됨’을 확인한다. 선택 이미지 초안은 IndexedDB가 지원되면 기기에 보관한다. 전송 전 댓글은 현재 창에만 있으므로 새로고침 전 제출한다. 업로드 선택 이유는 로컬 초안으로 보관한다. 업로드 성공 후 이미지·댓글은 서버 파일에 남아 새로고침과 서버 재시작 후에도 복원된다.
- 수업은 생성 후 7일간 보관한다. 만료 정리는 서버 실행 중 주기적 및 API 접근 때 처리한다. 종료와 영구 삭제는 구분한다. 브라우저에 저장된 개인 노트는 서버 만료로 지워지지 않으며, 공용 기기는 다운로드 후 사이트 데이터를 삭제한다. **사진·노트·권한 파일을 Git에 넣지 않는다.**
- 이미지 원본 JPG·PNG·WebP 10MB 이하를 브라우저에서 긴 변 1600px 이하 JPG로 다시 그려 메타데이터를 제거한다. 서버는 MIME·시그니처·2MB 한도를 검사한다. 조당 40개, 수업당 200개 게시물·100MB 이미지 한도와 게시물당 40개 의견을 둔다. SVG 등 실행 가능한 업로드는 받지 않는다.

## 검증

```bash
cd /workspace/Bflow-lab/color-studio
npm test
```

API 테스트는 임시 데이터 폴더와 임시 포트로 독립 실행한다. 실제 수업 기록을 수정하지 않는다.

브라우저 테스트는 Playwright와 Chromium이 필요하다. 현재 클라우드에는 준비돼 있다.

```bash
npm run test:browser
```

다른 개발환경에서는 Playwright 1.62.1을 별도 개발 의존성으로 준비하고 `CHROMIUM_PATH`에 설치된 Chromium 실행 경로를 설정한다. `COLOR_TEST_ARTIFACTS`로 화면 캡처 출력 디렉터리를 지정할 수 있다. 자세한 실행 결과와 미검증 범위는 VALIDATION.md를 참고한다.

QR 생성기는 저장소의 `vendor/qrcode.js`를 서버가 제공한다. 별도 외부 QR 서비스에 참여 주소를 보내지 않으며 해당 MIT 라이선스는 `vendor/LICENSE.txt`를 따른다.

Render 배포 절차와 비용 확인은 [RENDER.md](RENDER.md)를 참고한다. 전용 Blueprint 파일은 저장소 루트의 `render-color-studio.yaml`이다.

## 색 개념 문제의 정답 공개

학생이 1~5번 문제를 먼저 선택·배열한 뒤 강사 화면의 **색 개념 문제 · 정답 공개**에서 해당 문제의 공개 버튼을 누른다. 공개한 문제의 답과 해설만 워크북·발표 화면에 전달한다. 다시 숨기기도 가능하고 공개 상태는 서버 재시작과 새로고침 후에도 유지된다. 학생이 정답을 직접 여는 버튼은 제공하지 않는다. 3·4번 선택지는 A / B / 잘 모르겠다로 표시하고 4번은 두 색을 비교한다. 이는 개념 학습 예시의 답이며 개인의 계절 유형을 판정하는 기능이 아니다.

## 나의 컬러 노트 PDF

마지막 ‘나의 발견 모아보기’에서 좋아하는 색의 이야기·오늘의 발견·다음 시도를 작성하고 **나의 컬러 노트 PDF 저장**을 누른다. 본인 기록, 직접 공유한 이미지·이유, 받은 피드백을 Apple 스타일의 A4 PDF로 저장한다. 댓글 작성자의 별명·타인의 게시물은 넣지 않는다. 파일 앱/다운로드에서 실제 PDF를 확인한다. 이미지나 공유 기록을 확인하지 못하면 저장을 중단하므로 연결 후 다시 누른다. 텍스트 백업도 유지한다. 개발·폰트·검증 상세는 [report/README.md](report/README.md)에 있다.

## 수업 당일 보호 기능 (2026-11-13)

- 펠트지 비교의 미제출 사진은 활동 탭 이동 시 유지한다. IndexedDB를 사용할 수 있는 브라우저에서는 펠트지·스타일 사진 초안을 기기에 보관하고 새로고침 후 복원한다. 사진 보관 실패 시 알림을 표시한다. 다른 기기나 사이트 데이터 삭제 후에는 복원하지 못한다. 사진을 성공적으로 공유하면 해당 초안을 지운다.
- ③ 색 개념·펠트지 탐구와 ⑧ 스타일 단계 진입 시 자료 공유를 자동으로 연다. 강사는 ‘자료 공유 닫기’로 중단할 수 있다. 활동·타이머 시작/일시정지는 함께 동작하며, 단계 이동으로 진행 중 타이머가 초기화될 때 확인한다.
- 새 수업의 기본 시간은 10/15/25/15/5/60/10/30/10분, 총 180분이다. 기존 수업의 사용자 설정은 바꾸지 않는다. 6명 조의 실물 비교는 1인 8분 + 재비교 12분을 안내한다.
- 강사 진행 체크의 학생별 ‘조 수정’으로 오입장을 바로잡는다. 개인 기록은 유지한다. 이미 게시물 또는 댓글을 공유한 학생은 기존 조의 개인정보가 다른 조에 넘어가지 않도록 이동을 막는다. 반드시 자료 공유 전에 조를 확인한다. 학생은 스스로 조를 바꿀 수 없다.
- 상단 게시판은 자료·댓글 열람 전용이며 새 자료를 자동 갱신한다. ‘워크북에서 자료 올리기 · 의견 남기기’로 작성 화면에 이동한다.
- 강사 화면 ‘수업 전 확인 · 강사 권한 복구’에서 비밀 복구 코드를 발급하고 파일로 저장한다. 다른 브라우저의 첫 화면 ‘강사 권한 복구’에 6자리 수업 코드와 비밀 복구 코드를 입력하면 제어권을 복구한다. 서버는 코드 원문 대신 해시를 보관한다. 재발급하면 이전 복구 코드는 무효이며, 복구 시 이전 강사 인증과 발표 연결은 종료한다. 새 브라우저에서 발표 창을 다시 열어야 한다. **복구 파일을 학생에게 공유하거나 프로젝터에 띄우지 않는다.** 코드를 미리 저장하지 않았다면 기존 브라우저의 권한 없이 복구할 수 없다.
- 사진 디코딩은 브라우저가 지원하는 이미지 형식을 시도하고 JPG로 변환한다. HEIC 등 디코딩 실패 시 스크린샷/JPG로 다시 올리는 방법을 표시한다. 모든 휴대폰의 HEIC 지원을 보장하지 않는다.
- 마무리를 10분으로 확보하고 종료 전에 실제 PDF 파일 확인을 안내한다. 휴식 단계에서는 PDF 도구·글꼴을 미리 불러온다. PDF에는 공유 설명을 요약한 경우에도 개인 워크북의 원래 관찰 내용이 보존된다.

수업마다 새 방을 만들고 강사 화면의 만료일을 확인한다. Render의 실제 최신 배포/영구 디스크/교실 Wi-Fi는 코드 자동 테스트로 확인할 수 없으므로 운영 환경에서 점검한다. 수업 진행 중에는 배포하지 않는다.
